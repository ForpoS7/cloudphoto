\# cloudphoto



Консольное приложение для хранения фотографий в Yandex Object Storage

и генерации статического сайта-фотоархива.



\## Требования к окружению



\- Python <3.10> или новее

\- Terraform <1.5> или новее

\- Аккаунт Yandex Cloud с созданным облаком и каталогом

\- ОС: Windows 10/11 или Linux



\### Переменные аутентификации



Terraform (провайдер `yandex-cloud/yandex`) берёт учётные данные из переменных окружения:



| Переменная     | Назначение                          |

|----------------|-------------------------------------|

| `YC\_TOKEN`     | OAuth- или IAM-токен Yandex Cloud   |

| `YC\_CLOUD\_ID`  | Идентификатор облака                |

| `YC\_FOLDER\_ID` | Идентификатор каталога              |



Для работы `cloudphoto` с Object Storage нужен статический ключ доступа

сервисного аккаунта с правами на бакет:



| Параметр                | Назначение                       |

|-------------------------|----------------------------------|

| `aws\_access\_key\_id`     | Идентификатор статического ключа |

| `aws\_secret\_access\_key` | Секретный ключ                   |

| `bucket`                | Имя бакета                       |



Эти параметры сохраняются командой `cloudphoto init` в файл

`<\~/.config/cloudphoto/cloudphotorc>`:



```ini

\[DEFAULT]

bucket = <имя бакета>

aws\_access\_key\_id = <идентификатор ключа>

aws\_secret\_access\_key = <секретный ключ>

region = ru-central1

endpoint\_url = https://storage.yandexcloud.net

```



Ключи и токены не хранятся в репозитории.



\## Порядок сборки



1\. Клонировать репозиторий:



&#x20;  ```bash

&#x20;  git clone https://github.com/ForpoS7/cloudphoto.git

&#x20;  cd cloudphoto

&#x20;  ```



2\. Создать виртуальное окружение и установить приложение:



&#x20;  ```bash

&#x20;  python -m venv .venv

&#x20;  # Windows

&#x20;  .venv\\Scripts\\activate

&#x20;  # Linux

&#x20;  source .venv/bin/activate



&#x20;  pip install <-e .  или  -r requirements.txt>

&#x20;  ```



3\. Создать облачные ресурсы через Terraform:



&#x20;  ```bash

&#x20;  cd <terraform>

&#x20;  terraform init

&#x20;  terraform apply

&#x20;  ```



&#x20;  Terraform создаёт <сервисный аккаунт, статический ключ и бакет>.



4\. Настроить приложение:



&#x20;  ```bash

&#x20;  cloudphoto init

&#x20;  ```



&#x20;  Команда запрашивает идентификатор ключа, секретный ключ и имя бакета.



\## Команды



| Команда | Описание |

|---------|----------|

| `cloudphoto init` | Сохранить параметры доступа в конфигурационный файл |

| `cloudphoto upload --album ALBUM \[--path PATH]` | Загрузить фотографии из каталога в альбом |

| `cloudphoto download --album ALBUM \[--path PATH]` | Скачать фотографии альбома в каталог |

| `cloudphoto list \[--album ALBUM]` | Вывести список альбомов или фотографий альбома |

| `cloudphoto delete --album ALBUM \[--photo PHOTO]` | Удалить фотографию или альбом целиком |

| `cloudphoto mksite` | Сгенерировать и опубликовать статический сайт |



\## Схема организации облачного хранилища



Все данные хранятся в одном бакете:



```

<bucket>/

├── index.html          # главная страница сайта

├── error.html          # страница ошибки

├── album1.html         # страницы альбомов

├── album2.html

├── отпуск/             # альбом = префикс ключа

│   ├── photo1.jpg      # фотография = объект "отпуск/photo1.jpg"

│   └── photo2.jpg

└── test/

&#x20;   └── sample.jpg

```



\- Альбом — это префикс ключа `<альбом>/`, фотография — объект `<альбом>/<имя файла>`.

\- HTML-страницы сайта лежат в корне бакета.



Обоснование:



\- В Object Storage нет настоящих каталогов, ключи образуют плоское пространство имён.

&#x20; Префикс с `/` — стандартный способ имитировать каталоги, его понимают консоль

&#x20; Yandex Cloud и S3-совместимые клиенты.

\- Список фотографий альбома получается одним запросом `list\_objects\_v2` с параметром `Prefix`,

&#x20; отдельный индекс или база данных не нужны.

\- Удаление альбома сводится к удалению всех объектов с его префиксом.

\- Ключи HTML-страниц не содержат `/`, поэтому они не смешиваются с альбомами.

&#x20; По этой же причине символ `/` в названии альбома запрещён.

\- Сайт раздаётся из того же бакета через хостинг статического сайта. Относительные ссылки

&#x20; `альбом/фото.jpg` на страницах альбомов указывают прямо на объекты фотографий,

&#x20; копировать файлы не нужно.
